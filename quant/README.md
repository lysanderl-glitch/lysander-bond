# 板块动量 + 龙头策略：可回测实现

把「行业景气度 + 板块动量 + 龙头」这套交易规范翻译成可运行、可验证、
可证伪的代码，并在 A 股历史数据上统计它的胜率与期望收益。

> **免责声明**：本项目是研究框架，不是投资建议，作者不是持牌投资顾问。
> 回测结果不代表未来收益。

---

## 1. 体系由哪几块组成

一套能得出**可信**胜率的回测系统，必须有这五层。缺任何一层，跑出来的
数字都只是自我安慰：

| 层 | 模块 | 职责 | 做不好的后果 |
|---|---|---|---|
| 数据层 | `datasource/` | 抓行情/财务，统一口径，本地缓存 | 复权方式错 → 收益凭空多出几十个点 |
| 时点层 | `fundamentals.py` | 财报按**公告日**而非报告期释放 | 前视偏差 → 业绩策略纸面无敌 |
| 信号层 | `sector.py` `picker.py` | 规范 A/B 的逐条实现 | 规范条款互相冲突而不自知 |
| 执行层 | `backtest.py` | T+1 成交、涨跌停、整手、费率 | 高估收益 10~30% |
| 评估层 | `metrics.py` `report.py` | 胜率 + 盈亏比 + 置信区间 + 基准对照 | 把 beta 当成 alpha |

```
quant/
├── sector_leader/
│   ├── config.py          # 规范 A/B/C/D 的全部参数，改参数即改规范
│   ├── datasource/
│   │   ├── base.py        # 统一 schema 与口径约定
│   │   ├── akshare_ds.py  # 推荐的真实数据 provider
│   │   ├── eastmoney.py   # 只依赖 requests 的直连 provider
│   │   ├── synthetic.py   # 合成市场，无网环境验证管线
│   │   └── cache.py       # CSV 缓存（几千次请求，缓存是必需品）
│   ├── fundamentals.py    # 点位时点财务面板 ← 最容易出错的地方
│   ├── indicators.py      # 因果指标（截断重算必须一致）
│   ├── sector.py          # 规范 A：板块筛选
│   ├── picker.py          # 规范 B：龙头选取
│   ├── backtest.py        # 规范 C/D：介入、仓位、风控、退出
│   ├── metrics.py         # 胜率/盈亏比/期望/置信区间/集中度
│   ├── report.py          # Markdown 报告
│   └── cli.py             # 命令行
└── tests/                 # 13 个测试，主体是「证明没有偷看未来」
```

## 2. 数据怎么抓

### 需要哪几类数据

| 数据 | 用途 | akshare 接口 |
|---|---|---|
| 行业板块列表 | 规范 A 的筛选池 | `stock_board_industry_name_em()` |
| 板块指数日线 | 均线、放量、波段结构 | `stock_board_industry_hist_em()` |
| 板块成分股 | 规范 B 的选股池 | `stock_board_industry_cons_em()` |
| 个股日线（后复权+不复权） | 收益、涨跌停、最小买入额 | `stock_zh_a_hist(adjust="hfq" / "")` |
| 业绩报表（**含公告日期**） | 规范 A.3 / B.2 | `stock_yjbb_em(date="20240331")` |
| 交易日历 | 回测主循环 | `tool_trade_date_hist_sina()` |

### 量级与耗时

全市场约 5300 只股票 × 2 年日线，加上约 90 个行业板块和 8~12 期财报：

- 请求数约 **1.1 万次**，接口有频控，`sleep=0.3s` 下大约 **1.5~2 小时**
- 落地 CSV 约 **1.5~2 GB**
- 因此缓存不是优化项：抓一次存下来，之后调参重跑都走本地

### 三个必须守住的口径

1. **用后复权（hfq），不要用前复权（qfq）**
   前复权序列会随每次分红被整体重写——今天拉到的 2023 年价格，和 2023 年
   当时看到的价格不一样。等于把未来的分红信息塞进了历史价格。
   本项目同时保留未复权收盘价 `raw_close`，专门用来判断涨跌停和「一手多少钱」。

2. **财报按公告日释放，不按报告期**
   一季报报告期是 3/31，但多数公司 4 月下旬才披露。如果让策略在 3/31 就
   看到一季报，「业绩爬坡期介入」这个策略会在回测里表现得极好——因为它
   提前一个月知道了业绩。`fundamentals.py` 强制 `公告日 + lag` 才可见，
   `tests/test_no_lookahead.py` 会验证这一点。

3. **成分股的幸存者偏差要如实标注**
   免费数据源（akshare / 东财）只能给板块的**当前**成分股。用今天的成分
   回测两年前，等于事先剔除了这两年退市、被调出、暴雷的公司。这会系统性
   高估胜率。本项目的 provider 用 `members_are_point_in_time` 属性声明这
   一点，报告首屏会打警告。要根治只能上付费数据（Wind / Choice / 聚宽）
   的历史成分快照。

### 命令

```bash
pip install -r quant/requirements.txt
cd quant

# 1) 先自检数据源字段映射（强烈建议，省得抓两小时才发现字段错了）
python -m sector_leader selftest --source akshare

# 2) 跑回测（首次会抓数据并缓存）
python -m sector_leader backtest --source akshare \
    --start 2023-09-01 --end 2025-08-31 --out output -v

# 3) 参数敏感性
python -m sector_leader sweep --source akshare --out output

# 4) 样本内 / 样本外
python -m sector_leader walkforward --source akshare
```

无网环境用 `--source synthetic` 验证管线本身。

## 3. 让结果可信的七条

回测最大的风险不是亏钱，是**得到一个假的好结果然后拿真金白银去验证**。
这七条按「造假能力」从强到弱排列：

| # | 陷阱 | 高估幅度 | 本项目的处理 |
|---|---|---|---|
| 1 | 财报前视（用报告期当可用日） | 巨大 | `FundamentalPanel` 强制公告日 + lag |
| 2 | 幸存者偏差（用当前成分股回测历史） | 大 | 如实声明并在报告首屏警告 |
| 3 | 用信号日收盘价成交 | 大 | 一律 T+1 开盘成交，测试钉死 |
| 4 | 忽略涨跌停 / 停牌 | 中~大 | 涨停不可买、封死跌停不可卖，订单顺延 |
| 5 | 忽略成本 | 中 | 佣金 + 过户费 + 印花税 + 双边滑点 |
| 6 | 前复权序列 | 中 | 用后复权算收益，未复权判涨跌停 |
| 7 | 参数过拟合 | 中 | `sweep` 看敏感性 + `walkforward` 看样本外 |

关于第 7 条的判读标准：

- **敏感性**：好参数的绩效应当是参数的**连续函数**。如果止损从 8% 改到
  9% 年化就从 40% 掉到 5%，那 8% 不是规律，是这段数据的一个巧合。
- **样本外**：在前 60% 区间定参数，后 40% 只验证不回头改。样本外期望
  收益衰减一半以内算可接受，衰减到 0 附近说明前面在拟合噪音。

## 4. 怎么读结果：别只看胜率

单独一个胜率数字几乎没有决策价值。80% 胜率、盈亏比 0.2 的策略是净亏的。
报告始终把四个量放在一起：

```
期望收益/笔 = 胜率 × 平均盈利 − (1 − 胜率) × 平均亏损
```

在此之上，还有三件多数回测会漏掉、但直接决定结论成不成立的事：

**① 置信区间。** 两年 A 股跑出来通常只有几十到几百笔交易，胜率的标准误
很大。报告用 bootstrap 给出期望收益的 95% 区间——**如果区间跨过 0，那么
「这套策略有正期望」这句话在该样本上根本不成立**，无论点估计多好看。

**② 基准对照。** 板块动量策略天然吃 beta。牛市里随便买都赚钱，所以必须
和「等权持有同一股票池」对比。超额为负，说明你只是买了个高换手、高成本
的指数。

**③ 分信号归因。** 报告会按「入场信号类型」（涨幅龙头 / 业绩龙头 / 交集）
和「板块买点类型」（反转启动 / 回调）分别统计胜率与期望收益。一个组合
策略的总胜率往往掩盖了「其中一条腿在持续亏钱」的事实。

**④ 收益集中度。** 如果剔除最赚的 3 笔后策略就不赚钱了，那「胜率」描述
的不是你会遇到的分布，而是一次幸运的尾部事件。报告会算这个，并在集中度
过高时直接标红。

## 5. 本仓库沙箱内的验证结果

沙箱的网络策略封禁了全部 A 股行情域名（eastmoney / sina / xueqiu /
tushare / yahoo 一律 `CONNECT 403`），**因此这里没有跑过真实数据**。
以下是用合成市场（30 个板块 × 25 只个股 × 485 个交易日）跑出的结果，
用途仅限于证明管线正确：

```
交易 116 笔 | 胜率 47.4% | 盈亏比 2.98 | 期望收益/笔 3.69%
年化 42.6% vs 等权基准 12.1% | 最大回撤 -7.4%
最大连续亏损 9 笔 | 最赚 1 笔贡献总盈亏 29.8%、最赚 3 笔合计 50.1%
```

**这些数字不能当投资参考**——合成数据的生成过程里我植入了「龙头在行情期
日均超额 3bp」的假设，策略能找到它只说明代码能工作。

### 但实现过程发现了三个规范本身的问题

**① 规范 B.1 与 C.4 直接冲突。**
B.1 要选「涨幅前三的龙头」，C.4 又规定「距板块启动涨幅超 50% 不做首次
建仓」。而龙头恰恰就是涨幅最大的那批。实测：

| 候选类型 | 无追高限制 | 施加 C.4 后 | 淘汰率 |
|---|---:|---:|---:|
| 涨幅龙头 | 849 | 9 | **98.9%** |
| 交集（涨幅∩业绩） | 202 | 0 | **100%** |
| 业绩龙头 | 1660 | 1069 | 35.6% |

按字面执行，这套规范会**退化成纯业绩选股**，动量那条腿从未真正参与。

修正方向：C.4 的本意是「不在拉升末端接盘」，这应该用**乖离率**度量
（收盘价高于 MA20 多少），而不是「距启动点涨幅」。改成乖离率口径后，
三类信号都能正常触发（本项目默认 `chase_reference="ma_extension"`，
原口径保留为 `"campaign_start"` 可切换对比）。

**② 规范 A.2 的「回调确认」被「反转确认」吞掉了。**
原文是「反转确认 **或** 回调确认」。这个 OR 让回调那条路径几乎不起作用：
把 `max_retracement` 从 0.382 放宽到 0.80，回调成立的板块日增加 81%，
但最终合格日只增加 2%——多出来的日子早就被反转条件放行了。

也就是说，你在分析里判定为**最大执行风险**的「回调 vs 下跌中继」判别，
按字面实现后基本没有约束力。本项目把两条路径拆成可切换的三种模式
（`sector.confirm_mode`），才能分别统计各自的胜率：

| 模式 | 笔数 | 胜率 | 盈亏比 | 期望收益/笔 | 年化 | 期望 95% 置信区间 |
|---|---:|---:|---:|---:|---:|---|
| `either`（原文） | 116 | 47.4% | 2.98 | 3.69% | 42.6% | [1.17%, 6.74%] |
| `reversal`（只做反转启动） | 64 | 46.9% | **4.00** | **5.66%** | 32.8% | [1.54%, 11.04%] |
| `pullback`（只做回调） | 109 | 45.0% | 2.33 | 2.19% | 22.6% | [0.32%, 4.29%] |

两条腿的单笔期望差了 2.6 倍。**在真实数据上重跑这张表，是这套体系能给
你的最有价值的一个结论**——它直接告诉你该把执行精力放在哪一类买点上。
（合成数据上的具体数值不作数，方法作数。）

**③ 「跌破 20 日线」不加确认会自我毁灭。**
未加确认时，47 笔交易里大量是买入次日即被扫出——回调买点本就在均线
附近，日内噪音必然反复穿越。加了「连续 2 日收在均线下方 1% 之外」的
确认后，交易笔数与期望收益都明显改善。规范里写「跌破关键位无条件执行」
时，必须同时定义什么叫「跌破」。

### 样本外衰减

```
       笔数    胜率  盈亏比  期望收益     年化
样本内   55  49.1%  3.00   4.21%   39.5%
样本外   16  50.0%  1.87   1.39%    4.5%
```

即便在我自己造的、埋了龙头溢价的市场里，样本外期望收益也衰减了 67%。
真实市场只会更严重。这就是为什么第 3 节第 7 条不是可选项。

## 6. 已知局限

1. **规范 A.3 的三道基本面门槛只落地了一道半**。「分析师盈利预测上调
   家数」和「行业中观数据（价格/订单/开工率/库存）」免费源拿不到，
   本项目用业绩报表可算的三条（广度、加速度、水平）替代，并开放
   `external_gates` 钩子供你接入付费数据后注入。
2. **成分股非点位时点**，幸存者偏差无法用免费数据消除。
3. **未建模融资融券、涨跌停排队、大额冲击成本**。资金量大时实际滑点
   远高于 0.1%，`CostModel.slippage` 需要按自己的资金量重估。
4. **两年样本对「板块行情」这个事件而言太短**。一轮完整的行业景气周期
   常常 2~3 年，两年可能只覆盖 3~5 轮有效行情，几十笔交易的统计功效
   很弱。建议至少取 5 年，或把股票池扩到全市场以增加样本。

cd quant && python -m pytest tests/ -q

13 个测试，主体不是测「策略赚不赚钱」，而是测「策略有没有偷看未来」：
